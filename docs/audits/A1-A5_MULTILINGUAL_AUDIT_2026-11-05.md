Это частичные локализации/адаптации, а не завершённый перевод полного урока.

**Целевое решение:** один канонический набор схем для каждого урока. SVG-файлы хранятся отдельно в `assets/lessons/<lesson-id>/`; языковые HTML-версии подключают те же файлы. Локализуются подписи и альтернативные тексты через языковые данные/разметку, но не меняются состав, логика и геометрия схемы без отдельного редакционного решения.

## 3. Содержательная проверка A.5

Русская страница A.5 содержит 10 основных разделов, пять SVG-схем, один Python-пример, словарь и проверку понимания. Нельзя доказательно утверждать, что текущая страница короче конкретного исходного файла, пока исходный утверждённый конспект/черновик не сопоставлен построчно. Но как самостоятельный вводный урок оценки качества она имеет выявленные пробелы:

- нет отдельного объяснения ROC curve и ROC-AUC;
- PR curve упоминается, но Precision–Recall AUC и выбор PR/ROC при дисбалансе не раскрыты;
- нет полноценного раздела cross-validation и корректного выбора схемы валидации;
- практический Python-код показывает только регрессию; классификационные метрики не рассчитываются;
- отсутствует воспроизводимый практикум, в котором сравниваются baseline и несколько моделей;
- не раскрыта роль stratified split и группового разделения на практических примерах;
- не показан пример интерпретации метрик с учётом цены FP/FN на числовых данных.

**Вывод:** A.5 следует расширить. До получения исходного утверждённого материала корректнее называть это методическим усилением и устранением пробелов, а не дословным восстановлением утраченного текста.

## 4. Приоритетный план исправлений

1. Зафиксировать русские A.1–A.5 как канонические версии и утвердить структуру каждого урока.
2. Восстановить EN и ZH до полного покрытия каждого раздела, примера, формулы, задания, словаря и источников.
3. Вынести иллюстрации в общий канонический набор SVG на урок; подключать одинаковые файлы во всех языках.
4. Расширить A.5: ROC-AUC, PR-AUC, cross-validation, stratified/group/time split, классификационный и регрессионный практикумы, baseline comparison и анализ ошибок.
5. Проверить единый переключатель RU / EN / 中文, взаимные переходы между уроками и возврат к той же языковой версии.
6. Проверить локализованные каталоги, карту знаний, Track A и главную страницу.
7. Провести HTML/link/asset checks, затем desktop/mobile browser acceptance и GitHub Pages deployment verification.

## 5. Критерии приёмки

- У каждой страницы A.1–A.5 есть три полноценные версии.
- EN и ZH покрывают все смысловые разделы RU; перевод не заменяет подробный урок кратким конспектом.
- Все версии имеют одинаковые learning outcomes, примеры, упражнения, схемы и источники по смыслу.
- Для одного урока все языки используют один и тот же набор канонических SVG.
- Переключатель не ведёт на отсутствующие URL и сохраняет текущий урок.
- Все пять уроков корректно представлены в каталоге и карте знаний.
- Проверки исходников и фактической опубликованной страницы завершены отдельно.

## 6. Ограничения текущей проверки

- Проверены файлы в GitHub `main`; визуальный рендеринг в реальном браузере не выполнялся.
- Сравнение количества слов — индикатор масштаба, а не автоматическая оценка качества перевода.
- Сравнение SVG пока основано на количестве встроенных схем; покадровая/семантическая сверка каждой схемы остаётся отдельной задачей.
- Первичный утверждённый текст A.5 не найден в проверенных путях; его отсутствие не позволяет заявить о буквальном восстановлении исходника.
- Supabase live project и его миграции не проверялись.
