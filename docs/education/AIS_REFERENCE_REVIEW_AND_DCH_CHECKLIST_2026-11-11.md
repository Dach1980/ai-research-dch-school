# AI Interpretability School — актуальный анализ и чек-лист DCH

**Дата проверки:** 2026-11-11  
**Внешний референс:** https://ai-interpretability.school/  
**Исследовательский репозиторий:** https://github.com/Dach1980/ai-interpretability-course  
**Авторы:** Sabrina Sadiekh и Elena Ericheva  
**Связанный roadmap:** RM-02 и RM-12

## 1. Назначение

Этот документ объединяет первоначальную задачу изучения AIS, ранее выполненные аудиты и актуальную структуру публичного сайта. Цель — проверить, что DCH School использует AIS как методический и предметный ориентир, но развивает самостоятельную программу, собственные объяснения, примеры, схемы, лабораторные работы и оценивание.

Исследовательский репозиторий ai-interpretability-course является отдельной базой референсных материалов, анализа, сопоставлений и предложений DCH. Он не заменяет основной репозиторий сайта ai-research-dch-school.

## 2. Что показывает актуальный сайт AIS

Публичная страница на дату проверки содержит:

- Track A — XAI Practitioner: блоки 00–17 и 21–25.
- Track B — Math of LLMs: блоки 26–36.
- В Track A представлены интерпретируемые модели, причинность, heterogeneous effects, PDP/ICE/ALE, permutation importance, SHAP, LIME, Anchors, counterfactuals, CNN explanations, gradient methods, CAM, axiomatic methods, concept-based methods, attention, applied LLM analysis, agent behavior, evaluation, perturbation, attacks и углублённые блоки.
- Track B охватывает mechanistic interpretability, математические prerequisites, Transformer internals, features/circuits, representation geometry, probes/lenses, causal interventions, sparse autoencoders, safety, scientific rigor и developmental interpretability.

Публичная структура обновляется. Номера и состав модулей AIS нельзя считать постоянными идентификаторами DCH. В старых DCH-документах встречаются более ранние версии описания AIS; их следует актуализировать по мере предметного crosswalk, а не механически заменять цифры.

## 3. Восстановленная первоначальная задача

По RM-02, RM-12 и связанным документам DCH должен:

1. Изучить образовательную архитектуру AIS: направления, тематическую последовательность, названия, prerequisites, учебные результаты и навигацию.
2. Проверить доступные исходные материалы AIS и отделить прочитанные источники от тем, известных только по публичному каталогу.
3. Сопоставить содержание AIS с собственной программой DCH, не перенося чужие номера и не предполагая соответствие «один модуль AIS = один модуль DCH».
4. Восстановить и утвердить 40-позиционную программу DCH: 00–10 — общая фундаментальная база, 11–26 — Track A, 27–39 — Track B. Track C — отдельная LLM-программа; PY.1 — отдельная траектория Python.
5. Для каждого модуля DCH определить назначение, learning outcomes, уровень, prerequisites, зависимости и место в маршруте.
6. Устранить пересечения и пробелы между темами; отдельно удерживать различия между объяснением поведения модели, причинной идентификацией и mechanistic interpretability.
7. Разрабатывать собственные уроки по циклу: outcomes → объяснение → научные источники → пример → практика → оценивание с ответами → локализация → техническая и редакционная приёмка.
8. Проверять воспроизводимость кода и лабораторных работ.
9. Обеспечить согласованную навигацию, карту знаний, обычный каталог и понятный путь обучения.
10. Вести подтверждения и ограничения в Roadmap/Audit.

- Создан отдельный исследовательский репозиторий ai-interpretability-course и сохранены материалы по учебной архитектуре DCH.
- В основном DCH-репозитории сохранены анализы AIS: интерфейс, названия тем, планетная карта, правила интеграции источников.
- Проведены содержательные разборы доступных материалов AIS 00, 01, 02, 04 и 07.
- Для AIS Module 02 подготовлен анализ и предложение декомпозиции на 41 короткий урок.
- Для AIS Module 04 подготовлен анализ и предложение декомпозиции на 50 коротких уроков.
- Для AIS Module 07 подготовлен анализ и предложение декомпозиции на 24 коротких урока.
- Создана проектная архитектура Track A на 16 слотов (11–26), приняты отдельные решения о разделении причинности и heterogeneous effects и о месте оценки качества объяснений.
- Создана самостоятельная программа DCH с тремя направлениями A/B/C, каталогами, планетной картой и многоязычными страницами.
- Созданы собственные уроки и лабораторные материалы; урок 1.2.1 расширен, локализован и переведён в published после CI.

## 6. Приоритетный план оставшихся работ

### P0 — восстановить актуальную карту программы
1. Сверить актуальные публичные блоки AIS 00–36 с локальными аналитическими документами и содержимым отдельного репозитория.
2. Создать одну матрицу AIS topic → DCH theme/module/lesson UID.
3. Для каждой строки указать: source evidence, prerequisite, DCH coverage, gap, overlap, proposed action, confidence.
4. Отдельно пометить темы, которые доступны только как краткое описание на сайте и не были изучены по полному учебному материалу.
5. Завершить RM-02 только после утверждения полного DCH crosswalk и названий/зависимостей 40 модулей.

### P1 — Track A
1. Сверить предложение 16 модулей с актуальным AIS Track A.
2. Уточнить границы между interpretable models, causality, global/local post-hoc, deep learning explanations, LLM/agent analysis и evaluation.
3. Проверить дублирование и gaps в темах 11–26.
4. Зафиксировать core / optional / advanced и необходимые лабораторные работы.
5. Утвердить архитектуру, затем последовательно создавать DCH-уроки.

### P1 — Track B
1. Составить подробную карту AIS 26–36 → DCH 27–39.
2. Проверить prerequisites по линейной алгебре, calculus, probability, optimization, PyTorch и Transformer.
3. Развести representation reading, causal interventions, circuit discovery, SAEs, safety и evaluation.
4. Для каждого блока определить минимальную воспроизводимую лабораторную работу и compute requirements.

### P1 — качество уроков и платформы
1. Провести аудит существующих страниц по Lesson Design System.
2. Проверить RU/EN/中文 по смыслу, полноте, терминам, формулам, схемам и тестам.
3. Запустить код и практики в чистой воспроизводимой среде.
4. Проверить ответы и объяснения самопроверки.
5. Провести desktop/mobile, клавиатурную и screen-reader приёмку.

## 7. Методологические и правовые ограничения

- AIS — источник для исследования программы и педагогических решений, но не научное доказательство само по себе.
- Не копировать тексты, графику, задания, код и структуру страниц. Создавать самостоятельные формулировки и учебные артефакты.
- Существенные научные утверждения подкреплять первичными публикациями, официальной документацией и учебниками.
- Не назначать DCH module ID по аналогии с номером AIS.
- Не считать доступный каталог полным изучением урока, если сам урок/ноутбук/практика не были доступны.
- Не объявлять модуль или roadmap done до проверки всех критериев и доказательств.
