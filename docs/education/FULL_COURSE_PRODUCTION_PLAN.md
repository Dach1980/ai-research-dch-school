# Полный курс DCH School — производственный план и контроль состояния

**Дата фиксации:** 2026-11-08  
**Ветка:** main  
**Назначение:** единый план создания полноценных учебных материалов для всех направлений DCH School.  
**Статус:** утверждена цель производства; реестр уроков и производственные партии требуют последовательного уточнения.

## 1. Цель

Создать самостоятельную образовательную программу DCH School, а не набор кратких конспектов. Каждый опубликованный урок должен содержать:

- паспорт: ID, название, направление, модуль, уровень, время, prerequisites и инструменты;
- измеримые learning outcomes;
- проблемное вступление и интуитивное объяснение;
- последовательную теорию от базового уровня к углублённому;
- определения терминов, формулы и разбор обозначений;
- оригинальные схемы/графики с подписями, интерпретацией и alt-текстом;
- пошаговый разобранный пример;
- практику или эксперимент с вопросом, гипотезой, baseline, изменением условий, наблюдениями и выводом;
- ограничения, предположения, типичные ошибки и контрпримеры;
- задания на понимание, применение и критическую оценку;
- эталонные ответы с объяснениями и ссылками на разделы;
- итоги, глоссарий, связь со следующим уроком и проверяемые источники;
- эквивалентные по смыслу и глубине версии RU / EN / ZH.

Урок с программным кодом дополнительно получает воспроизводимую среду, зависимости, инструкции запуска, ожидаемый вывод и разбор результата. Для практических тем создаётся notebook или отдельный комплект лабораторных файлов.

## 2. Источники истины и ограничения

При производстве использовать в таком порядке:

1. Принятые решения DCH в `docs/management/`.
2. Текущий стандарт `docs/education/LESSON_STANDARD.md`.
3. Утверждённая рабочая архитектура Track A в `docs/management/TRACK_A_ARCHITECTURE_PROPOSAL.md`.
4. Публичные страницы направлений и текущий каталог.
5. Материалы AIS и другие внешние источники — как исследовательские референсы, но не как утверждённую программу DCH и не как текст для копирования.

Подтверждённая основная нумерация: 00–10 — общая фундаментальная база; 11–26 — Track A; 27–39 — Track B. Track C — отдельная программа по LLM. PY.1 — отдельная траектория Python.

**Неизвестные названия модулей 00–10 нельзя выдавать за восстановленные утверждённые названия.** Их нужно разработать как предложения DCH, пометить как proposed и согласовать. Точно так же нельзя считать, что перечисление тем на странице Track B уже является подробной программой уроков.

## 4. Порядок производства

Работать последовательно, не создавая фиктивные опубликованные страницы.

**Партия 0 — инвентаризация и реестр**
- Сверить все существующие страницы, JS-уроки, каталог, треки, notebooks и аудиторские документы.
- Составить единый реестр `module_id → lesson_id → title → prerequisites → outcomes → practice → languages → status`.
- Для каждого элемента различать статусы: confirmed, proposed, draft, reviewed, published.
- Устранить расхождения между страницами Track, каталогом и фактическими файлами.

**Партия 1 — завершение Module 11**
- Провести предметный аудит A.1–A.6 и отдельной главы XAI.
- Определить, какие темы уже покрыты, какие дублируются и какой материал действительно нужен для завершения Module 11.
- Зафиксировать последовательность уроков и только после этого обновить каталог.
- Проверить EN/ZH не только по наличию файлов, но и по полноте и смысловой эквивалентности.

**Партия 2 — Track A, Modules 12–26**
- Для каждого модуля сначала утвердить lesson map и prerequisites.
- Создавать уроки небольшими учебными единицами; сложные темы делить, а не перегружать одну страницу.
- Для методов XAI включать сравнение методов на одинаковых данных, контрольные эксперименты и ограничения.
- Для нейросетевых методов обеспечивать CPU-friendly демонстрации и отдельно описывать требования к GPU.

**Партия 3 — Track B, Modules 27–39**
- Сначала выстроить математические и программные prerequisites.
- Практику строить вокруг воспроизводимых экспериментов с открытыми моделями и инструментами.
- Включать контрольные вмешательства, абляции, отрицательные результаты и ограничения интерпретации.
- Итоговый проект должен иметь критерии воспроизводимости и научной проверки.

**Партия 4 — Track C, C0–C12**
- Сверить авторские материалы и текущие версии LM Studio, моделей, API и MCP SDK.
- Для каждого практикума фиксировать версии, конфигурации и альтернативы для разного оборудования.
- Не включать закрытые ссылки или чужие материалы без разрешения.

**Партия 5 — PY.1**
- Утвердить отдельную программу Python.
- Согласовать её prerequisites и точки перехода к C6 и практическим модулям Track A/B.
- Каждая тема сопровождается упражнениями и небольшими программами.

**Партия 6 — локализация и публикация**
- Сначала вычитать каноническую RU-версию.
- Подготовить EN и ZH версии с теми же разделами, примерами, заданиями, ответами и оговорками.
- Сверить SVG/диаграммы, подписи, alt-тексты, формулы и кодовые листинги.
- Только после проверок менять статус урока на published и добавлять его в публичный каталог/карту.

## 5. Quality gates для каждого урока

Применять `docs/education/LESSON_STANDARD.md` и его шкалу 0–2 по критериям. Порог публикации — не менее 23/28, без нулей по критическим критериям.

Дополнительные обязательные gates:

1. **Научная корректность:** ключевые утверждения проверены по первичным статьям, документации или авторитетным учебным источникам; область применимости и неопределённость раскрыты.
2. **Педагогическая целостность:** prerequisites соответствуют реальному содержанию; learning outcomes проверяются заданиями.
3. **Практическая воспроизводимость:** код/эксперимент запускается в заявленной среде; указаны версии, данные, baseline и ожидаемый результат.
4. **Мультиязычная эквивалентность:** EN/ZH не являются сокращёнными пересказами RU; совпадают учебные цели, ограничения, задания и ответы.
5. **Техническая целостность:** HTML валиден, ссылки работают, язык страницы корректен, навигация и переключатель языков работают, каталог проходит валидатор.
6. **Доступность:** изображения имеют alt, таблицы читаемы, интерфейс доступен с клавиатуры, мобильная версия пригодна для обучения.
7. **Публикационный статус:** draft/reviewed материалы не показываются как published и не получают фиктивного доступа.

## 6. Текущий первый шаг

Начать не с массового создания пустых HTML-файлов, а с завершения аудита Module 11:

1. Сопоставить A.1–A.6 с утверждёнными learning outcomes модуля 11.
2. Проверить отдельную главу XAI на полноту, уникальность и корректность места в последовательности.
3. Подготовить crosswalk: тема → существующий раздел → пробел → решение (reuse / revise / new lesson).
4. Утвердить финальный список уроков Module 11.
5. После этого выпускать следующую производственную партию и синхронно обновлять каталог.

**Критерий успеха:** каждый модуль имеет прозрачную карту уроков, каждый опубликованный урок является полноценным самостоятельным учебным материалом, а статус публикации подтверждается содержательными, языковыми и техническими проверками.
