## 1. Правило идентификации

- Номер урока берётся только из поля `code` каталога v3.
- Техническая идентичность урока задаётся его `uid`; короткий номер `code` — отображаемый учебный номер.
- Названия файлов и старые идентификаторы из прежнего каталога являются адресами/историческими псевдонимами, а не номерами уроков.
- Нельзя автоматически превращать старые обозначения страниц в номера уроков.
- Если старый HTML-материал сопоставлен нескольким UID, его нельзя объявлять одним уроком. Сначала нужно разнести проверяемые тезисы и компоненты по реальным урокам.
- Все изменения должны сохранять иерархию Track → Theme → Module → Lesson, текущие UID, коды и связи каталога. Новую систему нумерации не вводить.

## 4. Важные неоднозначности, которые нельзя скрывать

1. Историческая страница о машинном обучении и данных сопоставлена сразу с одиннадцатью записями каталога. Её вопросы и термины нельзя массово перенести в один урок. Каждый вопрос/термин необходимо отнести к тому целевому уроку, в котором соответствующий материал действительно объясняется.
2. Страница о модели машинного обучения включает сопоставление с `3.1.6`, хотя остальные цели находятся в теме 1. Это нужно проверить по содержанию и карте каталога отдельно; не переносить материал автоматически.
3. Словарь и самопроверка могут относиться к разным целевым урокам внутри одной исторической страницы. Их нужно распределять независимо, по учебным целям и фактическому тексту.
4. Целевые записи со статусом `planned` — элементы утверждённой структуры каталога, но это не означает, что для них уже опубликованы отдельные HTML-страницы. До готовности урока не создавать фиктивные опубликованные страницы и не менять статус каталога ради удобства аудита.

## 5. Исправленный план работ

### P0 — опубликованные уроки с однозначным соответствием

- Проверить и исправить самопроверку и словарь урока `1.1.1` по трём локализациям.
- Проверить и исправить самопроверку и словарь урока `1.1.4` по трём локализациям.
- Проверить уже существующие самопроверки и словари уроков `1.1.2` и `1.1.3`; не переносить их содержимое в другие уроки.
- Два неработающих yes/no вопроса находятся в исторической странице `lessons/a-4-what-is-machine-learning-model*.html`, которая сопоставлена нескольким UID: `1.4.1`, `1.4.2`, `1.4.5` и `3.1.6`. До исправления необходимо установить, какой именно тезис проверяет каждый вопрос, и привязать его к конкретному целевому уроку. Нельзя приписывать этот дефект уроку `1.1.4`.

### P1 — распределение материала исторических страниц по реальным целевым урокам

- Для каждой из исторических страниц, сопоставленных нескольким UID, построить карту: раздел исходного материала → целевой UID и код → тезис → вопрос/термин → объяснение/определение.
- Не назначать одному целевому уроку вопросы, которые проверяют материал другого урока.
- Для целей со статусом `planned` фиксировать подготовленный материал как кандидат на будущую разработку, не выдавая его за опубликованный урок.

### P2 — общий механизм и доступность

- После распределения содержания унифицировать самопроверки: radio для одиночного и yes/no выбора, checkbox для множественного.
- Добавить стабильные ID вопросов и проверку, что каждый ключ ответа соответствует существующему варианту.
- Сохранить все три локализации и смысловую эквивалентность, а не буквальное совпадение перевода.

### P3 — словари и регрессионные проверки

- Удалить дублирующие источники словарей только после сверки и объединения содержания.
- Убрать placeholder-термины, устранить дубли и выровнять смысловой охват локализаций.
- Сохранить подтверждённые объёмы словарей только там, где соответствующие термины действительно принадлежат конкретному уроку; не переносить число терминов как искусственный норматив на другой урок.
- Тестировать соответствие терминов и вопросов фактическим ID/UID, корректность ключей, типы input, полноту локализаций и отсутствие заглушек.
