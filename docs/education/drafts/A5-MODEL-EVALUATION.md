# A.5 — Как проверяют качество модели

**Track:** A — Understanding AI  
**Module:** 11 — Основы AI и машинного обучения  
**Статус:** подготовленный редакционный план / черновик следующего урока  
**Уровень:** Beginner  
**Планируемая длительность:** 60–70 минут  
**Prerequisites:** A.1–A.4

## Назначение урока

Учащийся уже знает, как модель обучается и что представляет собой обученная модель. Теперь нужно научиться проверять качество строго и честно: выбирать метрику под задачу, правильно делить данные, сравнивать с базовым решением и распознавать переобучение, утечку данных и сдвиг распределения.

## Результаты обучения

Учащийся сможет:
1. объяснить назначение train, validation и test выборок;
2. выбирать базовые метрики для регрессии и классификации;
3. интерпретировать confusion matrix, precision, recall и F1;
4. объяснить, почему accuracy может вводить в заблуждение при дисбалансе классов;
5. распознавать переобучение, недообучение и data leakage;
6. сформулировать ограничения проведённой оценки и не делать выводов сильнее имеющихся доказательств.

## Основная логика лекции

### 1. Почему «модель работает» — недостаточно
Показать модель с высокой точностью на обучающих данных и плохим качеством на новых. Сформулировать главный вопрос: какую оценку мы можем считать честной?

### 2. Разделение данных
- training set — настройка параметров;
- validation set — выбор конфигурации и гиперпараметров;
- test set — итоговая оценка выбранного решения.
Объяснить, почему нельзя многократно подбирать модель по тесту и затем считать тестовую оценку независимой.

### 3. Метрики регрессии
- MAE: средняя абсолютная ошибка;
- MSE: средняя квадратичная ошибка;
- RMSE: корень из MSE;
- R²: доля вариации относительно базового среднего, с важными оговорками.
Разобрать единицы измерения и чувствительность к выбросам.

### 4. Метрики классификации
- confusion matrix: TP, TN, FP, FN;
- accuracy;
- precision;
- recall;
- F1-score;
- threshold и trade-off между precision и recall.
Отдельно показать пример редкого аварийного события: модель «всё нормально» может иметь высокую accuracy и нулевую полезность для обнаружения аварий.

### 5. Выбор метрики под последствия ошибки
Ложноположительные и ложноотрицательные решения имеют разные последствия. Показать, что универсальной лучшей метрики не существует: выбор зависит от задачи, стоимости ошибок и требований эксплуатации.

### 6. Переобучение и недообучение
Сравнить train/validation curves; объяснить влияние сложности модели, регуляризации и объёма данных. Указать, что разрыв между train и validation — диагностический сигнал, а не единственное доказательство.

### 7. Утечка данных и некорректный протокол
Примеры:
- признак содержит целевой ответ;
- нормализация выполнена до разделения выборок;
- временные данные перемешаны случайным образом;
- дубликаты попали одновременно в train и test;
- preprocessing использует сведения из теста.
Показать правильную последовательность preprocessing внутри pipeline, обучаемого только на train.

### 8. Практический эксперимент
Синтетическая задача классификации аварийных событий с сильным дисбалансом классов:
- сравнить accuracy, precision, recall, F1;
- изменить порог решения;
- посмотреть confusion matrix;
- обсудить стоимость пропуска аварии и ложной тревоги.

### 9. Ограничения оценки
Метрика — не полная характеристика системы. Нужно учитывать качество разметки, репрезентативность выборки, временной сдвиг, группы пользователей/объектов, неопределённость оценки, эксплуатационные условия и мониторинг после запуска.

## Обязательные иллюстрации

1. Train / validation / test: назначение и границы использования.
2. Матрица ошибок 2×2 с TP, TN, FP, FN.
3. График train/validation loss для underfitting, нормального обучения и overfitting.
4. Precision–recall trade-off при изменении порога.
5. Пример временной утечки: случайное перемешивание против хронологического разделения.

## Терминология

Training set, validation set, test set, metric, baseline, MAE, MSE, RMSE, R², confusion matrix, true positive, false positive, precision, recall, F1-score, threshold, class imbalance, cross-validation, data leakage, distribution shift.

## Проверка знаний

Вопросы должны проверять:
- зачем нужна каждая из трёх выборок;
- почему нельзя оптимизировать модель по test set;
- выбор метрики для редких событий;
- интерпретацию FP и FN;
- обнаружение leakage в примере;
- ограничения переноса результатов теста в эксплуатацию.
