# Учебная архитектура DCH School: Track → Theme → Module → Lesson

**Дата:** 2026-11-08  
**Статус:** целевая модель и проектная карта; редакционные названия 00–10 и 27–39 требуют отдельного утверждения  
**Ветка:** main

## 1. Принятая иерархия

DCH School использует четыре уровня:

1. **Track (трек)** — самостоятельное направление обучения: Track A — Understanding AI; Track B — Inside AI; Track C — Building with AI.
2. **Theme (тема)** — крупная предметная область внутри трека, объединяющая несколько модулей.
3. **Module (модуль)** — целостная учебная единица внутри темы с собственными целями, результатами обучения, prerequisites и границами содержания.
4. **Lesson (урок / подмодуль)** — конкретная учебная единица внутри модуля. Уроки имеют собственные постоянные ID (например, A.1, A.2), страницы, локализации, практику и планеты знаний.

Иерархия: **Track → Theme → Module → Lesson**. Лабораторные работы, задания, checkpoints и тесты связываются с уроками и/или модулем, но не заменяют уроки.

## 2. Правила идентификаторов

- Основные позиции 00–39 — номера **модулей**, а не уроков и не тем.
- A/B/C — идентификаторы треков.
- Тема получает отдельный стабильный ID и название; тема не обязана иметь собственный сквозной номер.
- Модуль получает ID вида M00…M39 и номер 00…39.
- Урок сохраняет независимый lesson ID: A.1, A.2…; не переименовывается в M11.1.
- Для каждой сущности хранятся явные parent IDs: theme.track_id, module.theme_id, lesson.module_id. Дублирующее поле lesson.track_id допустимо только как производное/проверяемое поле совместимости.
- Переименование темы/модуля не меняет lesson ID и URL опубликованной страницы.
- Track C остаётся отдельной LLM Engineering программой, вне 00–39. PY.1 остаётся отдельной Python-траекторией.

## 5. Безопасная миграция существующего каталога

Текущий production-каталог использует schema_version 1:
- modules.json содержит M11 как единственный модуль и поле track_id;
- lessons.json содержит A.1–A.6 с module_id=module-11 и track_id=track-a;
- planets.json ссылается на lesson_id и не должен менять эти ID;
- опубликованные URL и языковые URL должны сохраняться.

**Не выполнять прямую массовую замену в текущем каталоге.** Целевая schema_version 2 должна добавить отдельные сущности/файлы themes и явные parent links:
- tracks.json — треки;
- themes.json — темы с track_id;
- modules.json — модули с theme_id и number;
- lessons.json — уроки с module_id; track_id может временно оставаться для обратной совместимости, но валидатор обязан проверять согласованность через цепочку родителей;
- planets.json — прежняя связь lesson_id без изменений.

План миграции:
1. Добавить JSON Schema v2 и тестовые fixture, не меняя production-каталог.
2. Добавить themes.json и подготовить каталог v2 параллельно с v1.
3. Написать dual-reader/compatibility adapter: старый интерфейс продолжает читать v1, новый умеет читать v2.
4. Проверить crosswalk каждого урока, включая RU/EN/ZH URL и prerequisites.
5. Добавить тесты неизменности lesson IDs, URLs, planet IDs и ссылок; тесты parent-chain, отсутствующих родителей, смешения треков и циклов.
6. Переключить renderer только после прохождения CI и визуальной проверки Pages.
7. Удалять v1 поддержку только отдельным решением после периода совместимости.

Для M11 установить parent chain: Track A → тема «Основы AI и машинного обучения» → M11 → A.1–A.6. Это сохраняет смысл ранее принятого решения о включении A.1–A.5 в M11 и текущую связь A.6, не меняя опубликованные страницы. Это проектная группировка темы; она не создаёт новых уроков.

## 6. Этапы выполнения и критерии завершения

- **ARCH-01 — Модель и карта:** документирована иерархия и все 40 позиций; неопределённые названия помечены proposed.
- **ARCH-02 — Каталог v2:** схема, миграция, совместимость, тесты и rollback; URLs и lesson IDs неизменны.
- **ARCH-03 — Перенос A.1–A.6:** все шесть уроков имеют проверенную parent chain Track A → Theme A1 → M11; локализации, prerequisites и планеты сохранены.
- **ARCH-04 — Содержательный аудит:** cross-language learning outcomes, теория, формулы, задания, ответы, источники; шесть отдельных scorecards.
- **ARCH-05 — Лаборатории:** извлечь код A.3–A.5 в воспроизводимые комплекты, закрепить версии среды/зависимостей, seed/data и expected output, запускать в CI.

Статусы нельзя переводить в done до получения доказательств CI, проверок ссылок и фактического выполнения лабораторных работ.

## 7. Ограничения и открытые решения

1. Предложенная карта M00–M10 и M27–M39 нуждается в содержательном согласовании; диапазоны и принадлежность треков подтверждены.
2. Тематические группы Track A A1–A5 — редакционная группировка, а не изменение утверждённых модулей.
3. Полный перечень уроков внутри M12–M39 не фиксируется заранее: он формируется после анализа learning outcomes и источников.
4. Никакие новые уроки не создаются в рамках миграции.
5. Track C и PY.1 не включаются в диапазон 00–39.
