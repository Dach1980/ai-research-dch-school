## 2. Важное разграничение источников

В проекте присутствуют три разных структуры, которые нельзя смешивать:

1. **Утверждённая основа DCH School из 40 модулей.** Из истории согласований подтверждается только общая схема: модули 00–10 — общая фундаментальная подготовка; 11–26 — Track A; 27–39 — Track B. Точные названия всех 40 модулей и полный первичный документ в доступных файлах репозитория не обнаружены. Следовательно, нельзя считать восстановленными все 40 карточек.
2. **Три направления визуальной архитектуры DCH:** Track A — Understanding AI; Track B — Inside AI; Track C — Building with AI. Эта структура закреплена в `reference/ai-interpretability-school/planetary-learning-map.md`. Она описывает навигационные направления школы, но сама по себе не содержит проверенного построчного соответствия 40 модулям.
3. **Публичная программа AIS (конкурента).** В PDF `01 introduction.pdf` описаны Track A — XAI Practitioner (23 пункта, включая self-check) и Track B — Math of LLMs (11 пунктов). Эти пункты — программа AIS, а не список модулей DCH. Нельзя переносить её номера или названия в DCH-каталог как утверждённые.

Также в карте DCH отдельно предусмотрена траектория `PY.1 — Python с нуля`, не входящая в A/B/C. Это отдельная траектория, а не дополнительный модуль в составе 40.

## 4. Что установлено по референсу AIS (не переносить в DCH как утверждённое)

PDF `01 introduction.pdf` перечисляет в Track A темы от Introduction, XAI motivation/terminology, linear and nonlinear interpretable models, causality, heterogeneous effects, PDP/ICE/ALE, SHAP/LIME/Anchors/counterfactuals, CNN explanations, gradient/CAM/axiomatic/concept/attention methods, LLM and agent analysis, evaluation, perturbation, attacks, SHAP/counterfactual deep dives и self-check. В Track B перечислены 11 крупных тем MI: introduction; mathematics prerequisites; transformers from inside; features and circuits; representation geometry; probes and lenses; causal interventions and applications; SAEs; applications and safety; evaluation/scientific rigor; developmental interpretability.

Это полезный референс для тематического покрытия и сравнения, но его нумерация и группировка не совпадают автоматически с DCH 40-модульной архитектурой.

### Prerequisites, подтверждённые только для AIS

В `01 introduction.pdf` указано:
- AIS Track A: школьная математика и основы высшей математики (производные, векторы); минимальный опыт Python/data analysis (pandas, numpy); знание основных классических ML-алгоритмов; базовые нейросети и PyTorch желательны.
- AIS Track B: линейная алгебра (матрицы, собственные значения, SVD); математический анализ (производные, градиенты, chain rule); backprop, архитектуры Transformer и PyTorch; чтение англоязычных первоисточников.
- AIS рекомендует Track A перед Track B, но также сообщает о частичном пересечении и возможности начинать с разных треков с учётом целей и подготовки.

Эти prerequisites нельзя автоматически присваивать модулям DCH. Их можно использовать как сравнительный ориентир после аудита собственной программы.

## 6. Выявленные проблемы и корректировки

1. **Нет доступного первичного списка 40 модулей.** В дереве `main` не найден `CURRICULUM_SCHOOL_MAP.md` и другой файл, содержащий полный перечень с названиями и описаниями.
2. **Ранее показанные в обсуждении примеры B.1–B.10 и C.1–C.13 не подтверждены как утверждённые элементы 40-модульной программы.** Не использовать их в качестве официальных планет до сверки с исходным curriculum map.
3. **Три сектора A/B/C и схема 00–10/11–26/27–39 — разные уровни классификации.** Нужна явная таблица crosswalk: `module_id → curriculum_group → track → planet_id`; нельзя выводить её только из названий треков.
4. **Состав Track C требует отдельного подтверждённого каталога.** Не следует приписывать его к 40 модулям XAI/MI без решения владельца программы.
5. **Prerequisites не документированы на уровне каждого DCH-модуля.** До получения исходной программы сохранять их как `unknown`, а не наследовать требования AIS.
6. **Нужно исправить раннюю формулировку о точном распределении тем.** Таблицы с примерами планет, приведённые в обсуждении 2026-11-04, являются концептуальными иллюстрациями и не прошли аудит на соответствие 40-модульному плану.

## 7. Рекомендуемая структура данных после восстановления источника

Для каждой записи модуля хранить:

- `module_id` — неизменяемый исходный ID (с сохранением утверждённой нумерации);
- `curriculum_order` — исходный порядок;
- `curriculum_group` — общая основа / Track A / Track B / другое, строго по первичному документу;
- `track_id` — A / B / C / PY или null, если соответствие не установлено;
- `title_original` и `title_ru` — исходное и локализованное названия;
- `technical_title` — научное/техническое название;
- `description` и `learning_outcomes` — только из утверждённого описания или отдельно согласованные редакции;
- `prerequisites` и `depends_on` — явные ссылки на ID, без inferred dependencies;
- `level`, `lessons`, `labs`, `duration`, `access`, `status`, `url` — только при наличии подтверждённых данных;
- `source_ref` и `audit_status` — происхождение каждого содержательного поля и состояние проверки.
