## 1. Утверждённая программа Track A

Пользователь утвердил базовую структуру Track A — Understanding AI: пять тем и 27 модулей. Полный перечень тем, модулей и предварительных уроков находится в [TRACK_A_CURRICULUM.md](../education/TRACK_A_CURRICULUM.md).

Принята последовательность:
1. Основы искусственного интеллекта и машинного обучения.
2. Инструменты, программирование и математические основы.
3. Модели машинного обучения и глубокое обучение.
4. Основы Explainable AI (XAI).
5. Продвинутые методы и исследовательская практика XAI.

Целевая глубина — практическая подготовка XAI Practitioner, а не обзорный курс.

**Статус названий уроков:** предварительная детализация утверждённой структуры. По мере разработки уроков названия, состав и порядок уроков можно дополнять и корректировать. Каждое содержательное изменение фиксируется в curriculum и истории решений с кратким обоснованием. Новые модули и темы не добавляются без пересмотра общей карты.

## 2. Утверждённая иерархия и нумерация

`Track → Theme → Module → Lesson`

- Track: устойчивый буквенный код и название, например Track A — Understanding AI.
- Theme: номер внутри Track, например Theme 1.
- Module: порядковый номер внутри Theme и содержательное название.
- Lesson: `<theme>.<module>.<lesson>`, например `1.2.1`.
- Нумерация уроков начинается заново в каждом модуле.
- Нумерация модулей начинается заново в каждой теме.
- Отображаемые коды не являются техническими первичными ключами.
- Все технические связи используют независимые стабильные UID.

## 4. Что необходимо исправить и завершить

### A. Программа и каталог
1. Записать утверждённую карту Track A в curriculum (выполнено этим обновлением).
2. Сверить фактический каталог, существующие уроки и прежнюю 40-модульную карту с новой программой.
3. Подготовить crosswalk: legacy code / legacy UID / URL → новый Theme / Module / Lesson code.
4. Не назначать старым урокам новые номера по догадке. В частности, прежний код A.1.2.1 — legacy identifier; его новое место определяется содержательным сопоставлением с утверждённой программой.
5. Спроектировать schema/catalog v3 со стабильными UID для Track, Theme, Module и Lesson.
6. Перевести все потребители каталога на UID и новые display codes с обратной совместимостью: prerequisites, переводы, прогресс, bookmarks, planet map, карточки, breadcrumbs, административные интерфейсы, URL и API.
7. Только после тестов переключить production catalog на новую модель.

### B. Дизайн и темы
1. Проверить, что переключатель Light / Dark / System присутствует в общем хедере всех типов страниц.
2. Проверить сохранение выбора и системную тему при первом посещении.
3. Исправить контраст текста, подписей, карточек, таблиц, схем и SVG в обеих темах.
4. Провести ручную проверку desktop и mobile; автоматические проверки считать только предварительным контролем.

### C. Код и педагогическая подача
1. Проверить реальную работу syntax highlighting на Python-фрагментах, включая функции, методы, классы, операторы, строки, числа, переменные и комментарии.
2. Проверить копирование исходного кода, номера строк, мобильную прокрутку и доступность.
3. Разделить длинные примеры на небольшие логические блоки.
4. Перед каждым блоком объяснять цель и контекст.
5. После блока объяснять новые конструкции, назначение операторов, функций, методов и параметров, ход выполнения и ожидаемый результат.
6. Добавлять практический эксперимент и типичные ошибки.
7. Не оставлять учебный код без объяснения; не считать подсветку синтаксиса заменой педагогического разбора.

### D. Текущие уроки и приёмка
1. Сопоставить прежний A.1.2.1 с утверждённой программой; не использовать legacy code как новый учебный номер.
2. После определения места переработать его по стандартам кода и иллюстраций.
3. Проверить RU / EN / 中文, обе темы оформления, desktop / mobile, клавиатуру и screen reader.
4. Сохранить review до полного прохождения Lesson Quality Gate.
5. Затем последовательно проводить аудит и обновление остальных существующих материалов.

## 6. Ограничения

- Не создавать новые уроки до согласования их места в утверждённой программе.
- Не считать legacy-коды новыми номерами.
- Не менять технические ID и URL без проверенной стратегии совместимости.
- Не менять статусы публикации автоматически.
- Не публиковать урок до прохождения quality gate.
- Дополнять и корректировать программу по мере разработки уроков; фиксировать изменения прозрачно.
- Track B (Mechanistic Interpretability) остаётся отдельным направлением и не включается в программу Track A.
