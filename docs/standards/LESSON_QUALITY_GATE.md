# DCH School Lesson Quality Gate

A lesson may be marked published only when all applicable checks are complete and evidence is recorded.

## 1. Curriculum and navigation
Correct Track / Theme / Module relationships; correct display code and stable technical UID; prerequisites resolve with no cycles or dangling references; RU / EN / 中文 routes work; breadcrumbs, lesson lists and planet-map references resolve; legacy URL aliases work where required.

## 2. Content and pedagogy
Learning outcomes are observable and assessed. Terms are introduced before use. Explanations are accurate, scoped and supported by sources. Examples distinguish correlation, attribution and causality. Code follows CODE_TEACHING_STANDARD.md. Figures follow ILLUSTRATION_STANDARD.md.

## 3. Interface and accessibility
Light / Dark / System themes work. Text, captions, code, tables and illustrations are legible in both themes. Desktop and mobile layouts are checked. Keyboard navigation and focus are usable. Screen-reader labels and alternative text are meaningful. Reduced-motion preference is respected.

## 4. Technical validation
HTML / JavaScript syntax checks pass. Catalog schemas and validators pass. Internal links and asset paths resolve. Code examples run in the documented environment. Copy controls preserve exact code. No page-wide horizontal overflow.

## 5. Localization
RU / EN / 中文 contain equivalent instructional sequence and meaning. Technical names, formulas, captions, references and warnings are consistent. Language attributes and navigation are correct.

## 6. Release decision
Record reviewer and date, automated test evidence, manual desktop/mobile evidence, accessibility review, scorecard and unresolved limitations.

CI success alone is not publication approval. A lesson remains review until manual acceptance is complete.
