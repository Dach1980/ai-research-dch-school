1.2.3 — 数据类型与特征表示

数值、类别、时间和文本特征：识别其含义，选择合适表示，并避免数据准备中的常见错误。

学习目标

完成本课后，你将能够：

  • 区分数值、名义类别、有序类别、时间和文本特征。
  • 解释为什么特征类型取决于含义，而不只是存储格式。
  • 选择基本的类别编码方式并理解其局限。
  • 发现单位、尺度和日期表示中的错误。
  • 在模型训练前制定特征准备计划。
核心问题一列数据看起来是数字，却可能只是类别代码。日期可能存储为文本、数字或日历事件。如何选择真正保留模型所需含义的表示方式？

1. 先理解含义，再判断数据类型

文件中的存储类型与分析中的特征类型并不相同。数值 `17` 可能表示年龄、房间号、地区代码或事件数量。并非所有情况都适合进行算术运算。

描述每个字段的含义、有效取值、单位以及何时可用。CSV 格式或 pandas 列类型只是技术线索，并不是语义定义。

2. 数值特征

定量特征表示测量值或计数。连续值可以在范围内变化（温度、面积）；离散值通常用于计数（请求数量、楼层数）。

检查单位和范围。摄氏度与华氏度是不同尺度；平方米与平方英尺必须先换算。零可能表示不存在，也可能只是尺度上的参考点。并非每个数值字段都适合求平均。

3. 名义类别与有序类别

名义类别表示没有自然顺序的类别，例如建筑类型、地区或请求类型。有序类别具有有意义的顺序，但不同等级之间的距离不一定相等，例如低、中、高。

地区代码 1、2、3 并不会让地区变成定量变量。模型可能错误地把代码的顺序和差值当作信息。名义类别常用独热编码；只有在顺序真实且理解模型限制时，才考虑有序编码。

4. 类别编码

独热编码为每个类别创建一个指示列，不会强加人为顺序，但会增加列数。唯一值很多的字段可能产生很宽的特征空间。

有序编码用代码替换类别，适用于顺序有意义，或模型与编码方案明确处理类别数据的情况。频率编码和目标编码需要谨慎：统计量只能在训练折内部计算，以避免信息泄漏。还要定义如何处理新出现的类别。

5. 日期与时间

日期不仅是字符串。它可以提取年份、月份、星期几、小时、季节或距事件发生的时间。合适的特征取决于问题和预测时点。

注意时区、夏令时变化、缺失值和日历周期。对于一天中的小时或星期几等周期变量，可以使用正弦和余弦表示，使 23:00 与 00:00 在数值上也保持接近。

6. 文本与标识符

文本字段可能是自由文本、短标签或结构化代码。根据任务和资源，可以使用分词、词袋、TF-IDF 或嵌入向量表示自由文本。

标识符有助于关联记录、分组和审计，但不一定是特征。唯一 ID 可能让模型记住行，或间接泄露目标。是否纳入 X 必须结合预测场景并检查泄漏风险。

7. 缩放与变换

缩放会改变数值范围；例如标准化会使特征居中并除以标准差。它对尺度敏感的方法很重要，但并非所有算法都需要。

对数等变换可能有助于模型，但必须符合字段含义和有效取值。任何需要从数据估计参数的变换（均值、标准差、类别词表）都只能在训练集上拟合，通常应放在 Pipeline 中。

8. 实践：建立特征说明表

考虑一个预测建筑每日能耗的数据表：`building_id`、`date`、`temperature_c`、`floor_area_m2`、`building_type`、`occupancy_plan`、`occupancy_actual`、`energy_kwh`。

为每个字段记录含义、特征类型、单位或有效类别、预测时点的可用性、表示方式和泄漏风险。预测明天时，明天的 `occupancy_actual` 尚不可用；`building_id` 可能用于分组，但是否放入 X 需要单独论证。

实践任务

为该数据表建立特征说明表。为 `building_type` 选择表示方式，从 `date` 提取至少两个日历特征，判断 `temperature_c` 和 `floor_area_m2` 是否需要缩放，并标出在当天开始前不能使用的字段。
