Training, Validation, and Test Data

Model evaluation is meaningful only when data used to fit, select, and finally assess a solution are separated without information leakage.

1.2.4

Learning outcomes

After studying this lesson, you will be able to:

  • Explain the distinct roles of training, validation, and test sets.
  • Choose a basic split strategy based on data structure.
  • Distinguish random, stratified, group, and time-based splitting.
  • Explain why preprocessing is fitted only on training data.

1. Why split the data?

If a model is evaluated on the same examples used for training, we mainly measure its ability to handle data it has already seen. Future performance must be assessed on observations that did not participate in fitting or selection.

A split simulates deployment: the model receives information available at prediction time, produces an output, and that output is compared with a target that was held back.

2. Three distinct roles

The training set fits model parameters and data transformations. The validation set supports model comparison, hyperparameter selection, threshold choice, and other development decisions. The test set is held untouched until the final assessment of the selected process.

If the model is repeatedly changed in response to test metrics, the test set gradually becomes part of the selection process. The final estimate is no longer independent and may be optimistic.

3. Choose a splitting strategy

Random splitting is suitable when observations are approximately independent and identically distributed. Stratified splitting preserves approximate class proportions, which is useful for classification, especially with imbalanced classes.

Group splitting is needed when multiple rows belong to the same person, building, device, or organization: entire groups stay together. For time-dependent data, train on the past and evaluate on a later period.

4. A time-forecasting example

To forecast December consumption, do not randomly mix December and January records across train and test if the intended task is predicting the future from the past. A more realistic design uses earlier months for training, the next period for validation, and the latest period for testing.

The boundaries should match the real forecast horizon and data availability. With seasonality, assess several time windows rather than relying on one favorable period.

5. Preprocessing can leak information

Imputation, scaling, category encoding, and feature selection are also fitted steps. Their learned values, such as the mean used for standardization, must be calculated on train only and then applied to validation and test without refitting.

If the mean is calculated or features are selected using the full dataset first, information from evaluation partitions leaks into training. Use a pipeline that fits every transformation inside each training fold.

6. Practice: design a split

Suppose a table contains hourly measurements from several buildings over three years. The goal is to forecast the next month for buildings already represented in the data. Time order matters, but holding out entire buildings is not essential if deployment concerns future periods for those same buildings.

Specify train, validation, and test time boundaries. Then change the requirement: the model must work on entirely new buildings. Explain why a group split by building is now needed and how the test scenario changes.
