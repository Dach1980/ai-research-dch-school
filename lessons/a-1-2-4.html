Результаты обучения

  • Объяснять разные роли обучающей, валидационной и тестовой выборок.
  • Выбирать базовую стратегию разделения с учётом структуры данных.
  • Различать случайное, стратифицированное, групповое и временное разделение.
  • Объяснять, почему предобработка обучается только на обучающей части.

Содержание урока

1. Зачем разделять данные

Если оценивать модель на тех же примерах, на которых она обучалась, мы измеряем в первую очередь способность работать с уже увиденными данными. Для оценки будущего поведения нужны наблюдения, не участвовавшие в настройке модели.

Разделение имитирует будущий сценарий: модель получает доступную информацию, строит прогноз, а затем результат сравнивается с ранее скрытой целью.

2. Три роли выборок

Обучающая выборка (train) используется для подбора параметров модели и обучения преобразований данных. Валидационная выборка (validation) помогает сравнивать модели, выбирать гиперпараметры, пороги и другие решения разработки. Тестовая выборка (test) остаётся нетронутой до финальной оценки выбранного процесса.

Если многократно менять модель, ориентируясь на тестовую метрику, тест постепенно становится частью процесса выбора. Итоговая оценка перестаёт быть независимой и может быть оптимистичной.

3. Как выбрать способ разделения

Случайное разделение подходит, когда наблюдения приблизительно независимы и одинаково распределены. Стратифицированное разделение сохраняет приблизительную долю классов, что полезно при классификации и дисбалансе.

Групповое разделение необходимо, если несколько строк принадлежат одному человеку, зданию, устройству или организации: целые группы удерживаются вместе. Для временных данных обучение обычно проводят на прошлом, а оценку — на более позднем периоде.

4. Пример временного прогноза

Чтобы прогнозировать потребление в декабре, нельзя случайно распределить декабрьские и январские записи между train и test, если модель должна предсказывать будущее по прошлому. Более честная схема: ранние месяцы — обучение, следующий период — валидация, самый поздний отрезок — тест.

Граница должна соответствовать реальному горизонту прогноза и доступности данных. При сезонности полезно проверять несколько временных окон, а не полагаться на один удачный период.

5. Предобработка и утечка

Заполнение пропусков, масштабирование, кодирование категорий и отбор признаков — тоже этапы обучения. Их параметры (например, среднее для стандартизации) нужно вычислять только по train, а затем применять к validation и test без повторного подбора.

Если сначала вычислить среднее или выбрать признаки по всему набору, информация из будущих оценочных частей проникнет в обучение. Используйте pipeline, который заново обучает все преобразования внутри каждого обучающего фолда.

6. Практикум: спроектируйте split

Предположим, в таблице есть почасовые измерения нескольких зданий за три года. Нужно прогнозировать следующий месяц для зданий, которые уже встречались в данных. Временной порядок важен, но группировать по зданию целиком необязательно, если цель — прогноз будущего для тех же зданий.

Опишите временные границы train, validation и test. Затем измените условие: теперь модель должна работать на совершенно новых зданиях. Объясните, почему потребуется групповое разделение по объекту, а тестовый сценарий изменится.
