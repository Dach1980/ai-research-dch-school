1.5.2 — 分类混淆矩阵

不要只看预测正确的比例，还要看分类器究竟犯了哪些错误。混淆矩阵把一组预测整理成四种结果，让错误结构一目了然。

学习目标

学完本课后，你将能够：

  • 解释混淆矩阵的用途，并正确读取行与列。
  • 根据真实类别和模型预测区分 TP、TN、FP 与 FN。
  • 根据带标签的分类结果建立矩阵，并核对总数。
  • 结合实际任务解释误报与漏报。
  • 说明矩阵能够描述错误结构，但不能单独决定哪个模型最好。
  • 理解矩阵如何扩展到多分类任务，以及标签顺序为何重要。
核心问题两个模型可能预测正确的对象数量相同，但一个模型漏掉更多危险事件，另一个模型产生更多误报。选择指标之前，怎样看出这种差异？需要按照真实类别与模型预测的组合拆分结果。

1. 从单个预测到错误结构

分类器接收一个对象，并将它归入预先定义的某个类别。获得可靠标签后，我们可以逐个比较预测结果与真实答案。只统计正确和错误的数量会丢失重要信息：对象真实属于哪个类别？模型又朝哪个方向判断错了？

混淆矩阵（confusion matrix）是一张同时展示真实类别和预测类别的表格。对于二分类任务，它包含四个单元格。每个单元格回答一个具体问题：对象在现实中是正类还是负类，模型又预测成了什么？

关键概念

混淆矩阵按照“真实类别—预测类别”的组合汇总分类结果，不仅展示错误数量，也展示错误类型。

本课把需要检测的事件定义为正类，例如零件缺陷或设备故障；没有该事件则为负类。正类不代表“好”，负类也不代表“坏”；它们只是技术标签。

2. 二分类混淆矩阵的结构

本课采用的方向是：行表示真实类别，列表示模型预测。先找到真实状态所在的行，再找到模型答案所在的列。两者交叉处的数字就是符合该组合的对象数量。

混淆矩阵：行是真实类别，列是模型预测
真实类别 \ 预测类别正类负类
正类TP真正例事件存在，模型检测到了FN假负例事件存在，模型漏掉了
负类FP假正例事件不存在，模型发出警报TN真负例事件不存在，模型正确判断为无事件

缩写由两个部分组成。True 表示预测与真实类别一致，False 表示预测错误。Positive 和 Negative 表示模型预测的类别。

3. 用实际例子理解四种结果

设想一套用于检查工业零件的系统。正类表示零件存在裂纹，负类表示零件没有裂纹。人工检查 200 个零件后，得到以下矩阵：

检查 200 个零件的示例结果
真实类别 \ 预测类别有裂纹无裂纹总计
有裂纹18TP2FN20
无裂纹12FP168TN180
预测总数30170200

TP = 18：系统检测出了 18 个确实有裂纹的零件。这些是有效检出。

FN = 2：系统把 2 个有裂纹的零件判断为完好。这是漏报：有缺陷的零件可能继续进入生产流程。

FP = 12：系统把 12 个完好的零件标记为有缺陷。这是误报：可能需要额外检查，造成延迟和不必要的成本。

TN = 168：系统正确放行了 168 个没有裂纹的零件。

一致性检查：四个内部单元格之和等于评估对象总数：18 + 2 + 12 + 168 = 200。行合计表示真实类别，列合计表示预测类别。

4. 为什么 FP 与 FN 不能混为一谈

这两个单元格都表示错误，但后果可能完全不同。在裂纹检测例子中，FN 是漏掉缺陷，可能导致产品失效；FP 是误报，会增加检查工作量和成本。哪种风险更重要，取决于系统用途，而不是单元格的名称。

再看其他场景：

  • 医学筛查：FN 可能意味着潜在疾病病例没有被转诊进一步检查；FP 可能让健康的人接受不必要的检查。
  • 垃圾邮件过滤：FP 可能把重要邮件放进垃圾箱；FN 可能让广告邮件进入收件箱。
  • 欺诈检测：FP 可能延迟合法交易；FN 可能让欺诈交易通过。

不能预先认定某一种错误永远更严重。应回到 1.5.1 课中的评估方案：明确谁会受到影响、后果是什么、决定能否撤销，以及是否有人复核警报。

关键区别

FP 表示模型报告了一个实际不存在的正类事件，即误报。FN 表示模型判断事件不存在，但实际上事件存在，即漏报。

5. 如何建立矩阵并避免弄反坐标轴

建立矩阵需要同一批对象的真实标签与预测结果。必须确认每个预测都与正确对象对应，并且两个序列采用相同的类别编码。

  1. 选择没有用于拟合模型的评估数据集。
  2. 明确指定哪个标签是正类。
  3. 逐个比较对象的真实标签与模型预测。
  4. 将对应的 TP、TN、FP 或 FN 单元格加一。
  5. 检查四个单元格之和是否等于对象总数，确保没有遗漏或重复计数。
  6. 把行列顺序与结果一起记录下来。

机器学习库通常允许显式指定标签顺序，不同绘图工具也可能采用不同方向。本课把真实类别放在行，把预测放在列。阅读其他工具输出的矩阵时，必须先检查坐标轴标签，否则可能把 FP 与 FN 对调。

6. 二分类与多分类矩阵

对于三个或更多类别的任务，矩阵会变成方阵：每一行代表真实类别，每一列代表预测类别。主对角线上的数值表示正确分类，非对角线上的数值表示错误。非对角线单元格的位置能显示模型混淆了哪两个类别。

例如，图像分类器需要区分猫、狗和鸟。“猫 → 狗”的错误与“鸟 → 猫”不同。只看错误总数无法发现具体混淆的类别组合。矩阵可以帮助定位这些模式，并判断是否需要更多数据、更好的特征或更清晰的标签。

在多分类任务中，可以针对某一个类别定义 TP、FP、FN 和 TN：把选定类别视为正类，把其他所有类别合并为负类。这种方法称为 one-vs-rest（一对其余）。各类别指标及其平均方式将在后续课程讨论。

7. 局限性与常见误读

  • 坐标轴颠倒：不看标题就可能把 FP 和 FN 对调。始终确认哪一轴是真实类别，哪一轴是预测类别。
  • 没有定义正类：TP/FP/FN/TN 的含义取决于哪个事件被定义为正类，必须明确说明。
  • 评估数据集不同：即使矩阵大小相同，如果数据组成和实验流程不同，也不一定能直接比较。
  • 标签本身有误：矩阵把参考标签当作真实标准，但人工标注也可能出错。
  • 缺少代价背景：矩阵统计结果数量，却不说明每种结果造成的损失。
  • 不是通用评分：矩阵描述观察到的结果，不能作为适用于所有任务的统一适用性指标。

如果只向矩阵提供最终类别预测，它也不会显示模型当时有多大把握。分析阈值和排序需要概率估计或分数，我们会在后续课程回到这一点。

实践任务：分析分类器结果

使用 200 个零件的矩阵，书面完成以下任务：

  1. 指出正类与负类分别是什么。
  2. 用自己的话解释 TP 中的 18 和 FN 中的 2 分别代表什么。
  3. 描述 FP 中 12 次误报可能造成的实际后果。
  4. 核对四个单元格的总和，并解释为什么它必须等于评估集大小。
  5. 举出一个 FN 比 FP 代价更高的场景，以及一个 FP 可能代价更高的场景。
  6. 画出一个三分类矩阵，标出正确预测的对角线以及一组被混淆的类别。

完成标准：能够正确识别四种结果，不混淆真实标签与预测，并把 FP/FN 与具体任务后果联系起来。现在不需要计算 Accuracy、Precision、Recall 或 F1；这些指标将在下一课学习。

本课总结

混淆矩阵展示真实类别与模型预测之间的关系。在二分类中，TP 和 TN 是正确结果，FP 是误报，FN 是漏报。它们的含义取决于正类定义和坐标轴方向。矩阵能够揭示错误结构、检查计数是否完整，并帮助讨论实际后果，但不能取代任务背景和评价指标。下一课将把这四个计数转化为 Accuracy、Precision、Recall 和 F1，并学习如何根据任务选择指标。
