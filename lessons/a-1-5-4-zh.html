核心问题在尚未确定工作阈值时，如何比较两个分类器？为什么同一个模型在 ROC 图上看起来不错，在 Precision–Recall 图上却可能没有那么理想？

1. 从单一工作点到多个阈值

在 1.5.2 和 1.5.3 中，我们使用混淆矩阵及其派生指标。二分类器通常先输出一个分数（score）或属于正类的概率，再通过阈值将分数转换为类别标签。

例如，模型估计设备发生故障的概率。阈值为 0.50 时，分数 0.72 会成为正类预测，分数 0.31 会成为负类预测。但 0.50 并不是自然定律：具体任务可能需要 0.30、0.70 或其他数值。

分类阈值（decision threshold）——将模型分数判定为正类预测的边界。降低阈值通常会产生更多正类警报；提高阈值则会减少警报。

每个阈值都会产生自己的混淆矩阵：TP、FP、TN 和 FN 随之变化，上一课中的 Precision、Recall、F1 等指标也会变化。ROC 和 Precision–Recall 曲线展示的是不同阈值下的一系列点，而不是单一工作点。

2. ROC 曲线：检出率与误报率

ROC 是 Receiver Operating Characteristic 的缩写。对每个阈值，计算两个量：真正例率（True Positive Rate，TPR）和假正例率（False Positive Rate，FPR）。TPR 等同于 Recall，表示所有真实正类中被检出的比例。FPR 表示所有真实负类中被错误预测为正类的比例。

真正例率（TPR）TPR = TP / (TP + FN) = Recall

符号说明：TP 是正确检出的正类；FN 是漏掉的正类。分母 TP + FN 包含所有真实正类。TPR 越高，模型检出的真实正类比例越大。

假正例率（FPR）FPR = FP / (FP + TN)

符号说明：FP 是错误的正类预测；TN 是正确识别的负类。分母 FP + TN 包含所有真实负类。FPR 回答：有多少比例的负类被错误地标记为正类？

ROC 图以 FPR 为横轴、TPR 为纵轴。每个阈值对应一个点。阈值非常高时，几乎没有对象被预测为正类，两种比率都接近零；阈值非常低时，几乎所有对象都被预测为正类，两者都接近一。

ROC 曲线——随着分类阈值变化，绘制 TPR 与 FPR 关系的曲线。它展示检出正类与产生误报之间的权衡。

3. ROC-AUC：ROC 曲线下面积

AUC 是 Area Under the Curve（曲线下面积）的缩写。ROC-AUC 将 ROC 曲线概括为一个数值。标准情况下取值范围为 0 到 1：越接近 1，说明模型越倾向于将正类对象排在负类对象之前。

ROC-AUC 的定义ROC-AUC = ∫₀¹ TPR(FPR) d(FPR)

这里 FPR 是 ROC 曲线的横坐标，TPR 是纵坐标。积分在整个 FPR 范围内累加曲线高度。实际计算通常根据有限个点进行近似，例如使用梯形法则。

它还有概率解释：随机抽取一个正类对象和一个负类对象，正类对象获得更高 score 的概率（相同分数通常按半分计入）。因此它衡量的是排序能力，而不是概率估计是否准确。

参考值：1.0 表示完美排序；约 0.5 表示接近随机排序；低于 0.5 可能意味着排序方向颠倒，或正类定义错误。该数值并不保证存在一个误报数量可接受的实际阈值。

注意：高 ROC-AUC 不会告诉你应该选择哪个阈值。应在 validation 数据上结合 FP/FN 成本和实际约束选择阈值，不要反复使用 test 数据调参。

4. Precision–Recall 曲线：正类预测的质量

ROC 中 FPR 的分母是所有真实负类。当负类数量非常大时，即使误报数量不少，FPR 仍可能很小。因此，在正类稀少的任务中，ROC 曲线有时会显得过于乐观。

Precision–Recall（PR）曲线在纵轴绘制 Precision，在横轴绘制 Recall，并随阈值变化。它聚焦于正类：找到了多少真实正类，以及正类预测有多可靠。

PR 曲线坐标x = Recall = TP / (TP + FN)y = Precision = TP / (TP + FP)

每个阈值都会产生一组 Precision/Recall。降低阈值通常会提高 Recall，因为检出的正类更多；但误报也可能增加，因此 Precision 往往下降。这是一种权衡，而不是图形缺陷。

Precision–Recall 曲线——不同阈值下 Precision 与 Recall 之间关系的图形，帮助评估正类预测的可靠性与覆盖程度。

5. PR-AUC 与 Average Precision 并不总是相同

PR-AUC 通常指 Precision–Recall 曲线下面积。但不同工具和论文可能使用不同的点间聚合方式。尤其是 Average Precision（AP，平均精确率），它是一种常见的阶梯式汇总方法：将 Recall 的每次增量乘以相应的 Precision 后求和。

Average Precision（AP）AP = Σₙ (Recallₙ − Recallₙ₋₁) × Precisionₙ

各点按阈值排序；Recallₙ 是当前点的召回率，Precisionₙ 是该区间对应的精确率。求和只累计 Recall 的正向增量。这不一定等于将相邻点线性连接后得到的梯形面积。

因此，报告必须说明具体计算方式：Average Precision、梯形法 PR-AUC，或某个库的特定实现。不要把不同算法得到的数值当作完全相同的指标比较。

PR 曲线不像 ROC 曲线那样有通用的随机对角线。它的基线 Precision 等于评估数据中正类的比例（prevalence）。如果正类仅占 2%，基线 Precision 约为 0.02。因此 PR 指标会受到正类比例影响。

6. 如何选择 ROC-AUC 或 PR-AUC

ROC-AUC 适合比较两个类别整体的排序质量：它衡量正类对象获得更高分数的频率。PR-AUC / AP 更适合正类是主要关注对象、同时重视 Precision 与 Recall 的场景，尤其是正类稀少时。

比较维度ROC-AUCPR-AUC / AP
坐标轴TPR 对 FPRPrecision 对 Recall
关注重点正类与负类的区分正类预测的质量
随机基线ROC-AUC 约为 0.5Precision 约等于正类比例
正类稀少时TN 很多时可能显得乐观更直接展示 Precision/Recall 权衡
不能提供具体阈值或概率校准具体阈值；且依赖正类比例及 AP/AUC 定义

实践流程：先定义正类和应用场景；在相同且独立的 validation 协议下比较 ROC-AUC 与 PR-AUC/AP；查看曲线本身；根据任务约束选择阈值；固定方案后再用 test 进行一次最终评估。如果关心具体工作点，还应报告该阈值下的 Precision、Recall、FPR 和混淆矩阵。

ROC-AUC 和 PR-AUC 都不能替代概率校准、错误成本分析、子群体评估以及部署后的监控。面积较大并不能证明模型公平、稳健或具有因果有效性。

7. 实例分析：为什么 ROC 与 PR 会讲述不同的故事

设想一个质量检测系统需要检查 10,000 个零件，其中 100 个有缺陷（1%），9,900 个正常。在某个阈值下，模型检出 80 个缺陷，漏掉 20 个，对 198 个正常零件误报，并正确识别 9,702 个正常零件。

因此 TPR = 80 / 100 = 0.80（80%）。FPR = 198 / 9,900 = 0.02（2%）。Precision = 80 / (80 + 198) ≈ 0.288（28.8%）。Recall = 80%。ROC 点为 (0.02, 0.80)，PR 点为 (0.80, 0.288)。

正常零件中的误报率只有 2%，但共有 278 个正类警报，其中只有 80 个是真正缺陷。因此 Precision 约为 28.8%。这并不矛盾：FPR 的分母是所有负类（9,900），而 Precision 的分母是所有正类预测（278）。

实践中，ROC 有助于理解两个类别的整体排序能力；PR 更直接地展示在给定 Recall 下团队会收到多少有用警报。对于稀有缺陷，应查看 PR 曲线和警报绝对数量，而不只看 FPR。

8. 局限、常见错误与可靠评估流程

  • ROC-AUC 不等于 Accuracy。AUC 评估多个阈值下的排序能力；Accuracy 计算单一阈值下的正确分类比例。
  • 高 ROC-AUC 不保证高 Precision。正类稀少时，即使 FPR 很小，也可能产生大量误报。
  • PR-AUC 依赖正类比例。比较正类比例不同的数据集时，应报告 prevalence 和数据协议。
  • AP 与梯形 PR-AUC 可能不同。必须注明计算方法和实现。
  • 面积不会自动选择工作阈值。应在 validation 上选择阈值，不能反复使用 test 调整。
  • 检查 score 方向。确保更高分数代表更强的正类证据，否则排序方向可能颠倒。
  • 使用独立观测。重复记录、时间泄漏和组间依赖都会使评估失真。
本课总结：ROC-AUC 与 PR-AUC 比较不同阈值下的排序质量，但回答的问题不同。ROC 绘制 TPR 与 FPR；PR 绘制 Precision 与 Recall。正类稀少时，PR 曲线尤其有用，同时必须报告正类比例和 AP/AUC 的计算方式。
