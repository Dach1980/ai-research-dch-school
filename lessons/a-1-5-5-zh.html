1.5.5 — 类别不平衡

理解为什么模型可能拥有接近完美的 Accuracy，却漏掉所有重要事件。学习衡量类别流行率、结合基准发生率解释指标，并在不污染评估数据的前提下处理不平衡。

学习目标

完成本课后，你将能够：

  • 定义类别不平衡并计算正类流行率。
  • 解释为什么高 Accuracy 可能与零 Recall 同时出现。
  • 根据 TPR、FPR 和正类流行率计算 Precision。
  • 比较分层划分、过采样、欠采样和类别加权。
  • 解释 SMOTE 原理及合成样本的局限。
  • 建立仅在训练数据内部执行重采样的流程。
  • 结合自然事件比例选择指标并报告结果。
核心问题 如果故障只占全部情况的 2%，为什么 Accuracy 为 98% 的模型仍可能毫无用处？如何在不扭曲最终评估的情况下改进稀有事件检测？

1. 什么是类别不平衡？

在分类任务中，不同类别出现的频率可能相差很大。如果正类——例如欺诈交易、罕见缺陷或设备故障——只占观测数据的一小部分，就称数据存在类别不平衡。这不一定是数据错误，也可能准确反映模型运行环境。

正类流行率（prevalence）是正类观测数量除以全部观测数量。如果 10,000 笔交易中有 200 笔欺诈交易，那么流行率为 200 / 10,000 = 0.02，即 2%。负类有 9,800 个，类别比例为 1:49。

正类流行率π = N₊ / (N₊ + N₋)π 是正类观测比例；N₊ 是正类数量；N₋ 是负类数量。该公式说明目标总体中有多少比例属于我们希望检测的事件。

不要把事件稀少与标注质量差混为一谈。不要仅仅因为 50:50 更方便训练，就强行平衡数据。首先确认观测比例是否代表目标环境、正类如何定义，以及事件频率是否随时间变化。

类别不平衡 — 不同类别的观测数量存在显著差异。

2. 高 Accuracy 陷阱

假设有 10,000 条观测，其中 200 条为正类、9,800 条为负类。一个简单分类器始终预测“负类”。它正确分类全部 9,800 条负类，却漏掉全部 200 条正类。Accuracy 为 98%，但正类 Recall 为零。

这称为多数类基线（majority-class baseline）：始终预测最常见类别的简单参考模型。复杂模型应在任务真正关心的指标上优于基线，而不只是提高总体正确率。

混淆矩阵计数为 TP = 0、FN = 200、FP = 0、TN = 9,800。Accuracy = (TP + TN) / N = 98%；Recall = TP / (TP + FN) = 0%。没有正类预测时，Precision 在数学上未定义；一些库按约定返回 0 并给出警告。

Majority-class baseline — 始终预测最常见类别的简单模型。

3. 流行率如何影响 Precision

Recall 和 FPR 分别在真实正类与负类内部计算。Precision 回答的是另一个问题：所有正类预测中有多少是真的。因此，它不仅取决于模型区分两类的能力，也取决于正类在实际数据流中的出现频率。

在 10,000 条观测中，流行率为 2%，即 200 个正类和 9,800 个负类。设 TPR = 0.80、FPR = 0.02，则 TP = 160、FN = 40、FP = 196、TN = 9,604。Precision = 160 / (160 + 196) ≈ 44.9%，Recall 为 80%。虽然 FPR 只有 2%，但超过一半的正类警报是误报。

根据 prevalence、TPR 和 FPR 表示 PrecisionPrecision = (TPR × π) / (TPR × π + FPR × (1 − π))TPR 是被发现的正类比例；FPR 是被错误标记为正类的负类比例；π 是流行率。即使 TPR 和 FPR 不变，降低 π 通常也会降低 Precision。

如果流行率降至 0.2%，而 TPR 和 FPR 保持不变，Precision 还会进一步下降。因此，相同的 ROC 特征并不意味着模型在不同人群中具有相同的实际警报价值。迁移模型时必须重新检查基准发生率和工作阈值。

4. 如何处理类别不平衡

类别加权（class weighting）会增加稀有类别错误在损失函数中的权重。简单方法是让权重与类别频率成反比。这使优化过程更加关注稀有样本，但不会创造新信息，而且可能增加误报。加权模型输出的概率有时需要单独校准。

过采样（oversampling）增加少数类样本；简单复制可能导致模型过拟合个别观测。欠采样（undersampling）减少多数类样本，可加快训练，但可能丢失有价值的信息。这些方法改变的是训练数据，而不是目标环境的真实分布。

SMOTE（Synthetic Minority Over-sampling Technique）在特征空间中对相邻少数类样本进行插值，创建合成点。它不只是复制数据行，但在类别特征、复杂类别几何结构、异常值或强特征依赖情况下，合成点可能不真实。没有一种方法保证提升，应在相同划分上与基线比较。

加权损失函数L = w₊ · L₊ + w₋ · L₋L₊ 和 L₋ 分别是正类与负类样本的平均损失；w₊ 和 w₋ 是类别权重。提高 w₊ 会增加稀有类别错误的影响，但不保证质量提升。

5. 分层抽样与防止数据泄漏

分层划分（stratified split）会在 train、validation 和 test 中保留近似相同的类别比例。当正类很少时，这一点很重要：普通随机划分可能导致某个子集中的事件过少，甚至完全没有正类。

分层划分不能替代正确的数据划分策略。如果多行属于同一客户、设备或患者，应按组划分。如果任务预测未来，则应使用时间划分。不能为了保持类别比例而破坏组间独立性或时间顺序。

先划分数据，再仅对训练子集执行过采样、欠采样或 SMOTE。如果在划分之前复制稀有样本，相同或近似样本可能同时进入训练集和测试集，从而造成数据泄漏并高估模型表现。在交叉验证中，每个 fold 都必须仅在训练部分重新执行重采样。

6. 如何评估稀有事件模型

从混淆矩阵和 TP、FP、TN、FN 的绝对数量开始。没有分母的百分比会隐藏规模：FPR 为 2% 意味着每 1,000 个负类观测中有 20 个误报；如果观测总量达到数百万，仍可能带来巨大工作量。

稀有事件检测通常应考虑 Recall、Precision、F1 或 Fβ、PR-AUC / Average Precision，以及每天警报数、审核比例、漏报成本和审核成本等运营指标。ROC-AUC 仍可描述排序能力，但不能直接表示特定流行率下某个阈值的警报 Precision。

应根据可接受工作量和错误代价，在 validation 上选择阈值。如果概率用于决策，还要单独检查校准。固定流程后，用 test 做最终独立评估。若部署环境的流行率不同于训练数据，Precision 可能变化，应记录并持续监测基准发生率。

7. 实例计算与常见错误

某监测服务处理 10,000 个事件：200 个真实故障和 9,800 个正常状态。模型给出 TP = 160、FN = 40、FP = 196、TN = 9,604。因此 Recall = 80%，Precision ≈ 44.9%，Accuracy = 97.64%。

多数类基线的 Accuracy 为 98%，但 Recall 为 0%。故障检测模型的 Accuracy 略低，却找到了 200 个故障中的 160 个。这说明比较必须反映应用目标。不过，196 个误报也必须与团队能力比较：如果每个警报都需要人工审核，当前阈值可能代价过高。

常见错误包括：划分前平衡整个数据集；在人工平衡的测试集上评估；让稀有样本副本同时进入训练集和测试集；把 SMOTE 当作通用方案；在 test 上选择阈值；只报告 Accuracy；不报告 prevalence；忽略组和时间依赖。

总结：类别不平衡会改变分类器质量的解释方式，但并不意味着数据错误。Accuracy 可能掩盖稀有类别上的完全失败；Precision 取决于 prevalence；重采样和 SMOTE 必须严格防止数据泄漏。可靠评估应结合混淆矩阵、正类指标、PR 分析、运营限制以及自然分布上的测试。
