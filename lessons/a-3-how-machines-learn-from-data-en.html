How Machines Learn from Data

Understand observations, features, targets, loss, optimization and generalization—and why memorizing examples is not the same as learning a useful pattern.

Learning outcomes
  • Define the key concepts accurately
  • Distinguish methods and system components
  • Explain the main workflow using diagrams
  • Identify limitations and describe validation
Approx. 60 minutes

1. A dataset is structured

A dataset contains observations (rows) and features (columns). In supervised learning, each observation also has a target: the value or class the model should predict. For building energy, features may include outdoor temperature, occupancy and time of day; the target may be daily energy use.

2. Features and target

A feature is information available at prediction time. The target is the quantity to estimate. Using information from the future creates data leakage and makes evaluation misleading.

3. Algorithm and model

The learning algorithm searches for parameters that make a model perform well on training examples. The model is the resulting parameterized relationship. A loss function measures disagreement between predictions and targets; an optimizer updates parameters to reduce that loss.

4. Gradient descent

Gradient descent changes parameters in a direction that locally reduces loss. The learning rate controls step size. A step that is too large can overshoot; a step that is too small makes training slow. Modern optimizers improve this basic iterative idea.

5. Learning settings

Supervised learning uses examples with targets. Unsupervised learning searches for structure without target labels, such as clusters or low-dimensional representations. Reinforcement learning uses interaction and reward signals.

6. Generalization

A useful model should work on new examples from the intended environment. Underfitting means the model is too limited to capture patterns. Overfitting means it adapts too closely to training examples and noise. Validation and test data help assess transfer.

7. Practical experiment

Fit a simple line to an energy dataset. Compare training error with error on held-out observations. Change model complexity or learning rate one at a time. Never use future information as a feature.

8. Review

Identify observations, features and target in a prediction task. Explain why low training error does not guarantee good performance on new buildings. Give an example of data leakage.

Key terminology

Observation
One example or record in a dataset, often represented by a row.
Feature
An input variable available to the model when it makes a prediction.
Target
The value or class the model is trained to predict.
Loss function
A mathematical measure of how far predictions are from target values.
Optimizer
A procedure that updates model parameters to reduce the loss.
Generalization
The ability to retain useful performance on new examples.

Worked example: predicting building energy use

One row may describe one building-day. Features available before the forecast could include outdoor temperature, occupancy schedule and day of week. The target is energy consumed during the forecast period. A meter reading from the end of that period is not a valid feature: it leaks the answer into the input. Split the data before fitting transformations and keep a final test period untouched.

From examples to an objective

For regression, a common loss is mean squared error: average the squared difference between each prediction and its target. Squaring makes large errors contribute more strongly. The loss is a training objective, not automatically the same as the business cost of a wrong prediction. Metric selection and model evaluation are covered in A.5.

A small gradient-descent example

For a line ŷ = w·x + b, training changes w and b to reduce the loss. If the line predicts too high for many examples, the gradient indicates how the parameters should move to reduce the average error. The learning rate scales that update. Training is repeated until a stopping condition is reached; it is not a guarantee of a global optimum.

Why data splitting matters

Use training data to fit parameters and preprocessing, validation data to compare choices, and test data for a final independent estimate. For time series, train on earlier periods and evaluate on later periods. For repeated measurements from one building or device, group-aware splitting may be needed to prevent related examples appearing in both partitions.

Python practice: fit and predict

import numpy as np
from sklearn.linear_model import LinearRegression

X = np.array([[-10], [-5], [0], [5], [10], [15]])
y = np.array([2100, 1950, 1780, 1600, 1450, 1280])

model = LinearRegression()
model.fit(X, y)                 # training
prediction = model.predict([[7]])  # inference
print(prediction[0])

Each row in X is one observation and each column is one feature. fit() estimates the model parameters from the examples. predict() applies the trained model to a new temperature. This small example illustrates the workflow; it is not a validated energy model for a real building.

Complete lesson: from observations to a trained model

Representing a learning problem

A dataset is a collection of observations. Each row usually describes one case, event or time point; columns contain variables. The input variables are called features and are often written as X. In supervised learning, the value the model should estimate is the target, commonly written as y. For a building-energy example, outdoor temperature, floor area and occupancy may be features, while measured daily energy consumption is the target. A feature must be available at the moment a prediction is made. Using a value recorded only after the event would create data leakage.

Before training, inspect units, missing values, duplicates, outliers, timestamps and how the target was measured. A model cannot repair a poorly defined target or systematically incorrect measurements. Data quality and the sampling process are part of the learning problem, not merely a technical prelude.

Algorithm, model, parameters and loss

The learning algorithm is the procedure that uses training examples to construct or adjust a model. The model is the mathematical or computational object used to map inputs to outputs. Its parameters are values estimated during training, such as coefficients in a linear model or weights in a neural network. A loss function quantifies how far predictions are from the target according to a chosen criterion. Training searches for parameters that reduce this loss, often subject to regularization or other constraints.

Loss is not identical to real-world value. Squared error penalizes large numerical deviations strongly; absolute error is less sensitive to extreme errors. In classification, cross-entropy is commonly used to train probabilistic predictions. The metric used to choose a model may differ from the loss used to train it, so both choices need justification.

Gradient descent in plain language

Imagine a simple model ŷ = w·x + b. The values w and b determine the line. Training evaluates how wrong the predictions are, calculates how the loss would change if each parameter moved slightly, and updates the parameters in a direction expected to reduce loss. The learning rate controls the update size. A rate that is too large may overshoot; one that is too small may make learning very slow. Real neural networks have many parameters, so optimization is performed using gradients and numerical procedures rather than visual inspection of a curve.

Different ways to learn

In supervised learning, examples have known targets. Regression predicts a numeric value; classification predicts a category or class probability. In unsupervised learning, there is no explicit target, and the goal may be grouping, compression or anomaly discovery. In self-supervised learning, the training signal is created from the input data itself, as in predicting a hidden part of a sequence. Reinforcement learning instead uses rewards from interaction. These settings answer different questions and require different evaluation designs.

Generalization, underfitting and overfitting

A model is useful when it performs well on new cases, not only on the examples it has seen. This ability is called generalization. An underfit model is too simple or insufficiently trained to capture the relevant pattern. An overfit model adapts to accidental details and noise in the training data, so its training score is strong but performance on new data is weaker. More complexity is not always better. Use validation data and a baseline to judge whether additional complexity produces a repeatable improvement.

Correct data splitting and leakage prevention

The training set is used to fit parameters and preprocessing. A validation set helps compare models, features and hyperparameters. The test set is reserved for a final independent estimate. Do not repeatedly tune a model against the test set; doing so gradually turns it into another validation set. For time-dependent problems, preserve chronological order. When multiple rows belong to the same building, patient or device, use group-aware splitting so related observations do not appear in both training and test partitions.

Fit imputers, scalers, encoders and feature selectors only on the training fold. Put preprocessing and the estimator into one Pipeline so cross-validation repeats the full process safely. Leakage can also occur through target-derived features, future information, duplicated records or preprocessing performed before splitting.

Worked example: daily energy use

Suppose a dataset contains outdoor temperature, floor area, occupancy and daily energy use. The target is energy use; the first three variables are candidate features. A linear regression model can provide an interpretable baseline. Compare its predictions with a constant baseline and inspect residuals by temperature and occupancy. If errors are systematically larger on very cold days, the relationship may be nonlinear or important variables may be missing. Do not conclude that a more complex model is better until it improves on held-out data.

Practical task

Design a small prediction study. Define one row, the target, at least three features and the moment when each feature becomes available. Explain how you will split the data, choose a baseline, measure error and detect leakage. Write down one reason the model could fail after deployment, such as seasonal change, sensor replacement or a change in building operation.

Additional practice: inspect the learning process

From a prediction error to a parameter update

For a regression task, the model produces a numeric prediction for each training example. A loss function combines the differences between predictions and known target values into a quantity the algorithm can optimize. Mean squared error gives larger deviations a disproportionately larger contribution because errors are squared. Mean absolute error is easier to interpret in the target's units and is less sensitive to a few extreme deviations. The choice should reflect the task and the consequences of different errors.

During gradient descent, the algorithm estimates how the loss changes with each parameter. It updates parameters repeatedly, recalculates predictions and evaluates the loss again. A training curve can reveal whether optimization is progressing, but a falling training loss does not prove that the model generalizes. Monitor validation performance as well and stop or simplify the model when additional training harms performance on unseen examples.

What a good experiment records

  • the exact target definition and units;
  • the feature list and the time at which each feature becomes available;
  • the dataset version and the rule used to include or exclude observations;
  • the split strategy and random seed, where applicable;
  • the baseline, model family, loss and hyperparameters;
  • training and validation metrics, plus a final test result used only once;
  • known limitations, missing variables and expected changes after deployment.

This record makes the experiment reproducible and helps distinguish a real improvement from a lucky split or a change in the data.
